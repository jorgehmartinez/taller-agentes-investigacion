# Integración con r-workflow-plugins

El taller consume `../r-workflow-plugins` (repositorio vecino en el entorno de desarrollo); no mantiene una implementación paralela ni modifica el EPIC.

La base inspeccionada es **r-analytic-core / r-analytic-coding-principles**: código orientado a investigación, modelos editables localmente y controles proporcionados. Los ejemplos de safe_cfa, preparación oculta y diagnóstico explican qué problema busca prevenir. Se presentan como ilustraciones, no como prueba experimental del rendimiento de una skill.

Las áreas de manejo de datos y análisis psicométrico aparecen en el catálogo como alcances en desarrollo, no como skills publicadas. Para incorporarlas se necesitan nombre real, versión o commit, alcance, recursos, requisitos y prueba con el agente elegido. Probar también un error conocido o una ambigüedad que deba revisarse humanamente.

Los puntos actuales de integración en presentacion/deck.qmd son `skill-real`, `skill-anatomia`, `skills-catalogo` y la práctica desde `caso-portada`. AGENTS.md enlaza el procedimiento y las normas del proyecto; no duplica la skill completa ni reemplaza protocolo o diccionario.

Una captura del archivo muestra su contenido, pero no que el agente lo haya cargado. La captura propia del MCP aparece documentada en `capturas-pendientes.md`, pero no demuestra activación de una skill. La lectura y uso reales se verificarán durante el ensayo del caso; no se exige una segunda captura. Solo se presentará una integración como comprobada tras ejecutar esa prueba.
